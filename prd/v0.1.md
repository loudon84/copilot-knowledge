# Copilot Knowledge 桌面端 Demo 改造 PRD

**版本：v0.1**
**项目：`loudon84/copilot-knowledge`**
**阶段：桌面端基础清理与知识应用 Demo**
**技术范围：Electron + React，不包含 `nodeskclaw-knowledge` 和 RAGFlow 实际接入**

---

## 1. 项目背景

`copilot-knowledge` 当前代码由 `copilot-autotask` 桌面项目初始化而来，保留了完整的 Electron、React、oRPC、TanStack Router、TanStack Query、Zustand、shadcn/ui 和测试框架，可以继续作为知识应用工作中心的桌面端基础。

当前代码仍然以 AutoTask、SRM 和 RPA 为业务核心，已有模块包括：

* 工作台
* 自动化任务
* 运行记录
* Artifact
* SRM 门户
* 流程模板
* RPA 组件
* Web Workspace
* Worker 和系统设置

当前导航、页面标题和业务入口仍全部使用上述领域。

本阶段不在现有 AutoTask 页面上追加知识库功能，而是先清理原业务代码，保留桌面基础设施和集团登录能力，再创建知识应用工作中心 Demo。

## 2. 当前代码分析

### 2.1 可直接保留的基础能力

当前项目已经形成清晰的三层结构：

```text
Electron Main
    ↓ oRPC
Preload
    ↓
Renderer Actions
    ↓
React Feature
```

初始化代码明确要求：

* Main、Preload、Renderer 分层
* Renderer 不直接访问 Node API
* Native 能力通过 IPC 和 `actions/` 暴露
* 页面放在 `features/`
* 路由保持薄层
* TanStack Query 管理服务端状态
* Zustand 管理本地交互状态

这些约束适合继续用于知识应用工作中心。

应保留：

```text
Electron Forge
Vite
React
TypeScript
TanStack Router
TanStack Query
Zustand
oRPC
Zod
shadcn/ui
Tailwind CSS
i18next
Vitest
Playwright
Electron safeStorage
```

### 2.2 登录能力已经具备

当前登录页面已经通过 oRPC 调用 Electron Main，并连接 `nodeskclaw-backend` 的：

```text
POST /api/v1/auth/account-login
POST /api/v1/auth/refresh
GET  /api/v1/auth/me
POST /api/v1/auth/logout
```

登录令牌使用 Electron `safeStorage` 加密保存，不直接存放在 Renderer。登录页面也已经提供 nodeskclaw 账号登录和服务地址设置。

该部分应继续保留，但需要完成领域重命名和安全修复。

### 2.3 登录与 Mock 模式当前存在冲突

当前 `AutoTaskAuthProvider` 使用统一的 `VITE_AUTOTASK_API_MODE` 判断运行模式。当模式为 `mock` 时，会直接注入固定的 Mock 用户并跳过登录页面。

这与本阶段要求冲突：

```text
用户登录、用户信息：真实 nodeskclaw 接口
知识库、知识集、文档、问答：Mock 数据
```

必须将“身份模式”和“知识业务数据模式”拆开。

### 2.4 当前没有独立用户中心

目前用户功能只有侧边栏底部下拉菜单，内容包括：

* 用户名称
* 用户邮箱
* 系统设置
* 退出登录

没有独立的 `/profile` 或 `/user-center` 页面。

当前 `/settings` 页面是 AutoTask 系统设置，包含：

* Web Workspace
* Worker
* Artifact
* 浏览器 Session
* Mock 延迟

不能作为知识应用的用户中心继续保留。

本阶段需要新建用户中心页面。

### 2.5 原 Mock 服务不应继续扩展

当前 `mock-api.ts` 是一个集中式 AutoTask Mock 服务，直接加载任务、SRM、Artifact、Worker、运行记录、流程和审计数据。

`autotask-api.ts` 又在 Mock 和 Remote API 之间切换，并向页面暴露 AutoTask 领域接口。

该结构可以参考，但不应继续在原文件中增加知识库逻辑。应删除 AutoTask 数据访问层，重新建立 `knowledge-service`。

### 2.6 Electron 安全问题

当前 BrowserWindow 配置为：

```ts
contextIsolation: true
nodeIntegration: true
```

并且每次应用启动都会执行：

```ts
await clearSession();
```

这会导致两个问题：

1. Renderer 仍具有 Node Integration。
2. 用户每次启动应用都会丢失已保存的登录态。

代码中还残留多个 `debugger` 调试语句。

必须在本阶段一并修复。

### 2.7 项目标识仍然错误

当前项目仍使用：

```text
package name: AutoTask-studio
productName: SMC-Copilot
description: SRM Automation Desktop Workbench
executableName: SMC-Copilot
installer: SMC-Copilot.exe
publisher: LuanRoger/electron-shadcn
```

需要全面替换为 Copilot Knowledge。

```text

```

```env

NODESKCLAW_AUTH_BASE_URL=http://127.0.0.1:4510
```

```ts
type KnowledgeDataMode = "mock" | "remote";
```


### 新建会话

必须先选择知识集：


### Mock 回答行为

1. 用户发送问题。
2. 显示“正在检索知识库”。
3. 延迟 400ms。
4. 显示“正在生成回答”。
5. 使用逐字输出模拟流式回答。
6. 返回 2～4 条 Mock 引用。
7. 点击引用打开文档详情。

回答数据可通过关键词匹配 Fixture：

```text
销售
财务
采购
合同
产品
权限
```

未命中关键词时返回通用 Mock 回答。

### 引用结构

```ts
interface KnowledgeCitation {
  id: string;
  documentId: string;
  documentName: string;
  knowledgeBaseName: string;
  version: number;
```
